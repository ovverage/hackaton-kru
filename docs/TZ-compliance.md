# Реализация кейса № 3 в Qorgau 0.5.2

Источник: предоставленный пользователем PDF «Кейс №3 КРУ и Qostanai Hub рус (2).pdf», страницы 1–2. На второй странице требуются локальная детекция телефона/лиц, взгляд/голова и защита среды тестирования; на первой указана демонстрация 16 октября 2026. Это карта реализации, а не протокол физической приёмки. Дополнительные продуктовые решения перечислены отдельно.

| Требование кейса | Текущая реализация | Проверяемая граница |
| --- | --- | --- |
| Телефон в руке или перед экраном | Локальный YOLO11n ONNX; два обнаружения ≥0,80 за ≤0,6 с; PHONE_DETECTED и материал события | Телефон должен быть видим. Полевая полнота/ложные блокировки измеряются отдельно |
| Момент подъёма телефона | Временная эвристика движения/удержания по рамкам; PHONE_AIM_REVIEW. Во время блокировки phone-анализ продолжается без дополнительного штрафа | Подъём — повод для ручного разбора, не доказательство фотографии |
| Наведение камеры телефона/попытка съёмки | Клип даёт преподавателю наблюдаемый контекст | Направление оптической оси и срабатывание затвора не установлены текущей моделью: полное требование не подтверждено |
| Взгляд вниз, влево, вправо | Дообученная continuous gaze CNN, адаптивная зона по девяти точкам; 6° запас; событие после пяти секунд, третий эпизод направления блокирует | Неуверенность/пограничная зона не штрафуются; угловая ошибка датасета не равна точности событий |
| Положение головы | MediaPipe Face Mesh и отдельная оценка поворота | Углы головы не складываются с CNN-лучом; при потере лица направление не выдумывается |
| Присутствие и второе лицо | YOLOv8n face + MediaPipe, временные SECOND_FACE_REVIEW/FACE_ABSENCE_REVIEW | Видимость лица — приближение присутствия; закрытая/обрезанная голова может быть пропущена |
| Alt+Tab, Ctrl+C/V, Win, PrtScn | WinAPI hooks и политика клавиш/буфера; восстановление фокуса | Win+Пробел намеренно разрешён для раскладки. Пользовательская защита не блокирует Ctrl+Alt+Del/администратора |
| Запрет смены вкладок | Собственный Qorgau Browser с одной web-view, без новых окон, с одним origin; автономная вкладка Chrome/Edge связана расширением | SSO/переходы между origin и реальная привязка внешнего браузера требуют приёмки |
| Посторонние окна/браузеры | Точная привязка окна/процесса, полный экран, ограничения ввода, surfaces на мониторах | Чужие процессы не уничтожаются; пользовательский процесс не равен системной политике kiosk |
| Одновременный локальный прототип | Windows EXE содержит модели/CPU runtime, камеру, правила, запись и защиту; кабинет получает события | Код/CI и реальные сценарии проверки различаются. Финальное свидетельство — принятый собранный EXE на целевом ПК |

Стек кейса приводится как предложенный способ: YOLO, MediaPipe и Python реализованы; вместо pyautogui/keyboard/Electron применены прямые WinAPI-вызовы и PySide6/Qt. Направление взгляда дополнено обученной CNN; это объяснимая инженерная реализация, а не утверждение, что в программе присутствуют неиспользуемые библиотеки.

## Дополнительные функции продукта

Два режима — онлайн и автономный; свой React/FastAPI-кабинет; преподавательские решения и подтверждённые команды; резервный пароль; проверка лица преподавателя с отдельным разрешением на шаблоны; RU/KK/EN; адаптивная калибровка с повтором плохих измерений; двухчасовое серверное хранение видео и резервные копии без видео. Эти функции расширяют сценарий, но не закрывают автоматически перечисленные ограничения.
