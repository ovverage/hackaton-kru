## Самостоятельная проверка жюри

Используется один Windows 11 Pro ПК с веб-камерой. В режиме GUARDED преподаватель управляет продолжением и завершением через пароль на экране блокировки; Ctrl+Alt+Q вызывает этот экран. Второе устройство не является обязательным условием. Подробные шаги находятся в `RELEASE_CHECKLIST.md`.

До прогона: установить обычный EXE 0.4.5, убедиться в регистрации, выбрать открытое окно теста и камеру, нажать «Готово», глядя на экран. Преподаватель выбирает работающий ПК и запускает сеанс. Затем показать один полный путь: событие → клип → решение с причиной → продолжение → завершение. Проверять настоящие пороги: три отклонения ≥5 секунд в одном направлении с возвратом на экран ≥1 секунды; телефон — в отдельном продолженном сеансе. Человеческий прогон и подписанное синтетическое серверное видео показываются раздельно.

В GUARDED экран LOCKED сопровождается перехватом ввода и ограничением выбранного окна. Полноту защиты подтверждает аппаратный протокол WINDOWS_ACCEPTANCE.md: пока он не выполнен, не заявлять защиту от всех обходов ОС. STRICT и экспериментальный SEB не использовать как доказанный режим.

Три последовательных успешных ручных прогона одной версии пока не проведены. Резервная запись должна быть снята с той же версией EXE, моделей и правил, подписана датой и показана как запись, а не живой сеанс. Синтетический стенд проверяет интерфейс и транспорт, но не точность камеры.

## Ответы на вопросы

| Вопрос | Ответ по текущим фактам |
| --- | --- |
| Можно ли выйти из теста? | GUARDED ограничивает выбранное окно, ввод и системные сочетания. Выход преподавателя — по паролю через Ctrl+Alt+Q. Процесс с правами пользователя не защищает от администратора, Ctrl+Alt+Del и принудительного завершения; STRICT выключен. Защита написана на Python через WinAPI: библиотеки pyautogui/keyboard не используются. Физические обходы проверяются отдельно. |
| Почему недостаточно полноэкранного окна? | Оно не доказывает запрет системных сочетаний, других процессов и перезапуска агента. Нужны испытанный управляемый профиль и защищённое взаимодействие компонентов. |
| Вы обучили собственную модель? | Дообучили готовый COCO YOLO11n для телефона на COCO и проверенных собственных фото. Классификатор направлений обучен по признакам MediaPipe на предоставленных видео. YOLOv8n лиц и MediaPipe остаются готовыми моделями. Исходники, разделение данных и результаты находятся в training/README.md и карточке моделей; прежний слабый gaze-кандидат не используется. |
| Какая точность? | Для телефона — отдельный тест из 108 фото исключённого участника и проверка реального ONNX: training/reports/phone-export-v2.json. Для взгляда balanced accuracy на development holdout 94,66%; при исключении целого участника — 91,93% / 77,33%. YOLO нашёл второго человека в 150/171 кадре; 21 пропуск не исключён из результата. Это ограниченные кадровые показатели двух людей, не точность блокировок всей аудитории. |
| Очки, плохой свет, чтение у края? | Исходная поза определяется по первому пригодному кадру: в этот момент нужно смотреть на экран. Есть ошибки при моргании и чтении справа; короткий таймер не доказывает устойчивость при долгом чтении у края. Неуверенное наблюдение прерывает пятисекундный таймер. Нужны новые люди и длительные записи с разными условиями. |
| Вы определяете списывание или съёмку? | Нет. Система отмечает наблюдаемые сигналы. Телефон вне кадра и нажатие затвора не определяются; поднятие телефона — эвристика для ручного разбора. |
| Что при ошибке? | Преподаватель смотрит клип и отклоняет событие с причиной. История остаётся; продолжение разрешается отдельной командой. |
| Если камера сломалась? | Возникает техническая блокировка; в GUARDED показывается экран LOCKED. Можно повторить настройку камеры, после чего преподаватель разрешает продолжение по паролю. Завершение по паролю доступно и при неисправной камере. Аппаратный сценарий ещё нужно пройти. |
| Если пропала сеть? | События и видео остаются в локальной очереди для повторной доставки. В GUARDED потеря связи на 10 секунд вызывает блокировку. Доступность внешнего теста зависит от его размещения. |
| Где видео и звук? | Анализ локальный, звука нет. На сервер уходят клипы событий. Удаление через 7 дней с возможностью продления; резервные архивы ротируются отдельно. |
| Работает на 50 ПК? | Для 0.4.0 проверены 50 программных клиентов за 122 секунды: 3074 запроса, p95 214,69 мс, 0 ошибок и 50 синтетических клипов. Исторический двухчасовой HTTP-прогон 0.3.0: 181 293 запроса, p95 195,6 мс по последним 100 000 запросам, 13 ошибок (0,0072%). Полевого испытания 50 камер не было. |
| В чём новизна? | В сочетании подготовленного подключения, локального анализа и разбора доказательств на своём сервере. Готовые модели не объявляются изобретением команды. |
| Сколько стоит внедрение? | До пилота нет подтверждённой суммы. Учитываются сервер, диск, камеры, подготовка, поддержка и лицензии; формула и поля замера в PILOT.md. |
| Готово ли на 100 баллов? | Оценку выставляет жюри. Объединённая реализация, автоматические проверки, материалы и сценарий подготовлены; физическая приёмка, точность на новой съёмке, эффект пилота и репетиция требуют живых доказательств. Их перечень — в SCORECARD.md. |
