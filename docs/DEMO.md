## Самостоятельная проверка жюри

Используется один Windows 11 Pro ПК с веб-камерой. В режиме GUARDED преподаватель управляет продолжением и завершением через пароль на экране блокировки; Ctrl+Alt+Q вызывает этот экран. Второе устройство не является обязательным условием. Подробные шаги находятся в `RELEASE_CHECKLIST.md`.

До прогона: скачать подготовленный для кабинета EXE, убедиться в регистрации, выполнить калибровку, назначить сеанс и проверить доступность тестовой страницы. Затем показать один полный путь: событие → клип → решение с причиной → продолжение → завершение. Проверять настоящие пороги: три отклонения ≥5 секунд в одном направлении с возвратом на экран ≥1 секунды; телефон — в отдельном продолженном сеансе. Не смешивать человеческий прогон с подписанным синтетическим серверным видео.

В GUARDED экран LOCKED сопровождается перехватом ввода и ограничением выбранного окна. Полноту защиты подтверждает аппаратный протокол WINDOWS_ACCEPTANCE.md: пока он не выполнен, не заявлять защиту от всех обходов ОС. STRICT и экспериментальный SEB не использовать как доказанный режим.

Три последовательных успешных ручных прогона одной версии пока не проведены. Резервная запись должна быть снята с той же версией EXE, моделей и правил, подписана датой и показана как запись, а не живой сеанс. Синтетический стенд проверяет интерфейс и транспорт, но не точность камеры.

## Ответы на вопросы

| Вопрос | Ответ по текущим фактам |
| --- | --- |
| Можно ли выйти из теста? | В основной сборке наблюдения Windows не ограничена. STRICT запрещён до проверки реальной защиты. Подготовлен экспериментальный SEB адаптер. |
| Почему недостаточно полноэкранного окна? | Оно не доказывает запрет системных сочетаний, других процессов и перезапуска агента. Нужны испытанный управляемый профиль и защищённое взаимодействие компонентов. |
| Вы обучили собственную модель? | Поставляется upstream YOLO11n и MediaPipe. Подготовлены обучение и оценка на добровольно предоставленных данных; локальное дообучение пока не проводилось. |
| Какая точность? | На людях ещё не измерена. Цели из ТЗ не выдаются за результат; будут TP/FP/FN, precision/recall и интервал неопределённости. |
| Очки, плохой свет, чтение у края? | В калибровке есть края экрана; неуверенное наблюдение не увеличивает пятисекундный таймер. Реальная устойчивость по этим условиям требует размеченных испытаний. |
| Вы определяете списывание или съёмку? | Нет. Система отмечает наблюдаемые сигналы. Телефон вне кадра и нажатие затвора не определяются; поднятие телефона — эвристика для ручного разбора. |
| Что при ошибке? | Преподаватель смотрит клип и отклоняет событие с причиной. История остаётся; продолжение разрешается отдельной командой. |
| Если камера сломалась? | Возникает техническая причина и логическое LOCKED; восстановление камеры само по себе не разрешает продолжение. Аппаратный сценарий ещё нужно пройти. |
| Если пропала сеть? | События и видео остаются в локальной очереди, повторная доставка предусмотрена. Доступность внешнего теста зависит от его размещения. |
| Где видео и звук? | Анализ локальный, звука нет. На сервер уходят клипы событий. Удаление через 7 дней с возможностью продления; резервные архивы ротируются отдельно. |
| Работает на 50 ПК? | Двухчасовой HTTP тест 50 клиентов завершён: 181 293 запроса, p95 195,6 мс по последним 100 000 запросам, 13 ошибок (0,0072%). Отдельный двухминутный тест включает 50 синтетических клипов. Он не доказывает работу 50 камер и всей видеонагрузки. Полевого испытания 50 ПК не было. |
| В чём новизна? | В сочетании подготовленного подключения, локального анализа и разбора доказательств на своём сервере. Готовые модели не объявляются изобретением команды. |
| Сколько стоит внедрение? | До пилота нет подтверждённой суммы. Учитываются сервер, диск, камеры, подготовка, поддержка и лицензии; формула и поля замера в PILOT.md. |
| Готово ли на 100 баллов? | Максимум задаёт жюри. Реализация и материалы подготовлены частично; защита Windows, точность и пилот требуют доказательств. |
