# Демонстрация Qorgau 0.5.2

Показать один завершённый сценарий на Windows x64: подготовка → калибровка → защищённый тест → наблюдение → материал события → решение преподавателя → завершение. Исходные видео с людьми держать в личном демонстрационном архиве; в публичной документации использовать разрешённые снимки интерфейса.

## Подготовить перед показом

Скачайте оба EXE одного выпуска, сверяйте `SHA256SUMS.txt` и версии моделей. Проверьте камеру, свет, выбранный монитор, наличие свободного места и настоящий адрес теста. Встроенный браузер допускает один origin: заранее пройдите вход без внешнего SSO/всплывающих окон. Для автономного показа подготовьте локальную программу или связанную вкладку.

Демонстрационный сайт: **admin / admin**. Новый автономный профиль: резервный пароль **admin**; уже заданный пароль сохраняется. Эти данные предназначены для открытой демонстрации, перед реальными экзаменами их заменяют. Интерфейс можно показать на русском, казахском и английском; смена раскладки — отдельное разрешённое действие.

## Маршрут на пять минут

| Время | Действие | Что объяснить |
| --- | --- | --- |
| 0:00–0:35 | Открыть кабинет, показать подключённый ПК и создать сеанс | Система работает поверх сайта/программы теста без обязательного модуля LMS |
| 0:35–1:25 | Начать сеанс и пройти девять точек по три секунды | Личная зона взгляда учитывает монитор; плохая точка повторяется, а не считается успешной |
| 1:25–2:00 | Читать экран, перевести глаза, отдельно повернуть голову | Углы и подсказка — наблюдение; неопределённость не даёт штрафа; длительный эпизод учитывается отдельно |
| 2:00–2:40 | Показать телефон, получить блокировку, вызвать преподавателя | Телефон фиксируется локально; подъём — повод для разбора, не доказательство нажатия затвора |
| 2:40–3:30 | Открыть доступный клип и принять решение, разрешить продолжение | Решение и разблокировка различаются; команда подтверждается агентом |
| 3:30–4:15 | Завершить онлайн-сеанс, показать выбор автономного режима | Автономный контроль не отправляет события в кабинет; пароль работает без связи |
| 4:15–5:00 | Показать карточку модели и границы внедрения | Обучение, сохранённые метрики, краткие материалы, пилот на целевой площадке |

Повторы калибровки и задержки сети увеличивают время. Для жёсткого регламента заранее подготовьте подписанную резервную запись той же версии. Запись называйте записью. Нельзя демонстрировать синтетические события как результат распознавания человека. Если требуется показать три эпизода взгляда по пять секунд, выделите дополнительное время и возвращайтесь на экран минимум на секунду между эпизодами.

## Что проверяет жюри самостоятельно

После подготовки камера и модели работают уже при калибровке. До её завершения контроль не начинается. В защищённом тесте проверьте обычное чтение и края экрана, глаза без поворота головы, голову без сознательного перевода глаз, телефон, второе лицо, отсутствие лица и вызов преподавателя. Смена раскладки должна работать, Alt+Tab и другие ограниченные действия — соответствовать [протоколу Windows](WINDOWS_ACCEPTANCE.md).

При любой блокировке обычные gaze/face-события приостанавливаются, а телефон продолжает создавать материалы для разбора без дополнительных штрафов. После разрешения используются свежие кадры. При окончании локального экзамена материалы удаляются; при онлайн-окончании собранная очередь синхронизируется. Полная последовательность — [RELEASE_CHECKLIST.md](RELEASE_CHECKLIST.md).

## Короткие ответы

| Вопрос | Ответ |
| --- | --- |
| Где выполняется AI? | На CPU компьютера студента. GPU использовался при обучении; на сервер идут короткие материалы событий. Проверка лица преподавателя дополнительно выполняется сервером. |
| Что обучили? | MobileNetV3 для направления взгляда на MPIIFaceGaze и Gaze360; рабочий YOLO11n телефона ранее дообучен на COCO и проверенных собственных фото. Новые кандидаты COCO/WIDER не прошли критерии и не заменили рабочие детекторы. |
| Какая точность? | Средняя угловая ошибка 7,681° на 2 997 пригодных MPII-кадрах и 13,217° на 17 847 пригодных Gaze360-кадрах; покрытие соответственно 99,97% и 68,72%. Это условные датасетные метрики, не точность блокировки экзамена. [Карточка](MODEL_CARD_2026_10_07.md). |
| Почему не показываете общий процент уверенности? | Вероятность телефона, неопределённость угла и правильность решения о нарушении — разные величины. Недоступное измерение не заменяем придуманным процентом. |
| Работает с любой LMS? | Нет обязательной зависимости от Moodle/Platonus. Выбирается сайт или программа, но совместимость авторизации, origin и действий теста проверяют на площадке. |
| Насколько защищает? | Собственный браузер, ограничения ввода и фокуса, привязка окна/процесса и восстановление. Это пользовательская Windows-защита, не защита от администратора или Ctrl+Alt+Del. |
| Факт фотографирования доказан? | Нет: обнаружение телефона и его подъём — наблюдения. Направление объектива и срабатывание затвора текущий конвейер не устанавливает. |
| Что с данными? | Нет аудио и непрерывного серверного потока. Онлайн-видео доступны два часа после загрузки; метаданные и решения сохраняются. Резервные копии содержат базу без видео. Автономные материалы остаются на ПК до завершения. |
| Готово к внедрению? | Есть функциональный MVP для контролируемого пилота. Реальные камеры, люди, тестовая платформа, безопасность, регламент и эффект проверяются отдельно; государственной аттестации нет. |
| Чем отличается от других решений? | Собственный локальный CV, адаптивная калибровка, автономный режим и свой кабинет в одном проекте. Сравнение SEB/Respondus по официальным источникам находится в README; превосходство точности не заявляется. |

Презентации 0.4.x и прежние кадры сохраняются как история; их фразы об отсутствии калибровки, старом классификаторе взгляда и семидневном серверном видео не относятся к 0.5.2. Текущий сценарий не доказывает проведённую репетицию: дату, хеш EXE, фактический результат и отклонения фиксируют после показа.
