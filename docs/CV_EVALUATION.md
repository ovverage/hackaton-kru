# Проверка и обучение CV

Сборка 0.3.0, правила 3.0, модели 2026.10.06.1. Дата: 6 октября 2026 года.

## Что поставляется

YOLO11n, предварительно обученный разработчиком на COCO, экспортирован в ONNX. Искомый класс — `cell phone` (67). MediaPipe Face Landmarker используется для числа лиц и признаков глаз/головы. Модели, CPU runtime и FFmpeg включены в EXE; скачивания модели при запуске нет. Происхождение и SHA-256 — в `model-manifest.json`. Модели не обучались на записях этой аудитории: подходящих размеченных данных пока нет.

Калибровка содержит центр, четыре края экрана и три направления вне экрана; по 25 подходящих кадров на позицию. Неуверенное наблюдение становится UNKNOWN и прерывает непрерывный пятисекундный таймер. Вероятное поднятие телефона — отдельная эвристика движения и удержания, требующая ручной проверки. Она не определяет направление объектива и факт съёмки.

## Протокол до получения данных

До настройки порогов сохранить неизменяемые идентификаторы участников, разделение train/val/test, список сценариев и правила разметки. Не помещать одного участника или соседние кадры ролика в разные выборки. Требуется добровольное информированное участие; имена в файлах заменять случайными кодами. Видео хранить в `.local/cv-data`, вне Git. Обычные экзаменационные записи не использовать для обучения автоматически.

Минимальная программа из R08: 5 участников, 60 положительных и 60 похожих отрицательных эпизодов телефона; 30 каждого направления, 30 второго лица, 30 отсутствия лица, 20 поднятий телефона и 20 похожих действий; 5 студент-часов обычного чтения. Проверить очки, разные допустимые освещение и посадку. Условия за пределами испытанного диапазона не включать в обещания продукта.

Разметка интервалов — JSON-массив:

```json
[{"recording":"P01-test-01","type":"PHONE_DETECTED","start":12.0,"end":18.5}]
```

Типы должны совпадать с событиями `shared/rules.py`: `PHONE_DETECTED`, `GAZE_DOWN`, `GAZE_LEFT`, `GAZE_RIGHT`, `SECOND_FACE_REVIEW`, `FACE_ABSENCE_REVIEW`, `PHONE_AIM_REVIEW`. Технические причины проверяются отдельно. Два разметчика независимо отмечают начало/конец; расхождения разбираются до просмотра предсказаний. Сценарии с блокировкой записывать раздельно либо учитывать реальные команды продолжения: offline replay не имитирует разрешение преподавателя.

Для каждой записи подготовить калибровку того же участника и положения камеры. Формат `calibration.json`: `centres` с восемью ключами из `agent/behavior.py`, каждый содержит четыре числовых признака. Альтернатива: `intervals` с восемью парами начала/конца калибровочных позиций в этом ролике и `score_from` — начало оцениваемой части после калибровки. Для каждой позиции требуется 25 кадров с одним лицом.

```powershell
.venv\Scripts\python.exe scripts/replay_cv.py .local/cv-data/P01.mp4 --calibration .local/cv-data/P01-calibration.json --recording-id P01-test-01 --output .local/evidence/replay-P01
.venv\Scripts\python.exe scripts/evaluate_events.py .local/cv-data/truth.json .local/evidence/replay-P01/predictions.json --output .local/evidence/metrics-P01.json
```

Replay использует производственный CV и часы видеозаписи; сохраняет наблюдения, события, SHA-256 исходника и p95 времени обработки. Запись без кадров не даёт показателя производительности. Для общего отчёта объединить предсказания и эталон по всем независимым роликам.

Совпадение: одна запись, один тип, взаимно однозначная пара с IoU интервалов ≥0,5; кандидаты выбираются по убыванию IoU. Повтор предсказания считается FP. Публиковать TP/FP/FN, precision/recall и 95% интервал Wilson. Этот интервал описательный: эпизоды одного участника зависимы; малая выборка не доказывает качество для всех студентов. Нулевой знаменатель обозначается `null`, а не 100%.

## Дообучение телефона

Разметить прямоугольники телефона в YOLO-формате: `0 cx cy width height`, нормированные координаты. Пустой label-файл — отрицательный пример. Манифест:

```json
{"items":[{"split":"train","subject":"P01","consent":true,"image":"images/P01-001.jpg","labels":"labels/P01-001.txt"}]}
```

Это только пример структуры, недостаточный для запуска. Скрипт требует минимум 20 разных изображений в каждой выборке и 5 участников, отклоняет дубли и пересечение участников. Минимум запуска не заменяет требования к эпизодам R08. Среда обучения отдельная: Python 3.12, Torch 2.6.0 CPU, Ultralytics 8.3.221, ONNX 1.17.0. Torch в студенческий EXE не входит.

```powershell
.local/model-build/Scripts/python.exe scripts/train_phone.py .local/cv-data/dataset.json --epochs 30 --output .local/training/run-01
```

Кандидат обучается на train, выбирается по val, оценивается на test и экспортируется в ONNX. Он не заменяет релизную модель автоматически. Для продвижения нужны сравнение на независимых эпизодах, проверка ошибок, новый manifest с хешами, новая версия модели и полный EXE self-test. После просмотра test для следующего цикла подбора нужна новая независимая проверочная выборка.
