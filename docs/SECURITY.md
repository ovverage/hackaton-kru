# Защита и границы прототипа

Версия 0.4.1. OBSERVE сохраняет доступ к рабочему столу; GUARDED ограничивает окно и ввод средствами Windows. Сервер по-прежнему отклоняет STRICT.

## Автоматическая регистрация обычного установщика

Публичный клиент содержит только HTTPS-адрес нашего сервера. На сервере `PROCTOR_PUBLIC_ENROLLMENT_OWNER` указывает существующего преподавателя; вне настроенного развёртывания регистрация по умолчанию выключена. Клиент не выбирает владельца и не получает права преподавателя.

Секрет установки создаётся на ПК до запроса и сохраняется локально. Повтор запроса возвращает прежнее устройство и токен; в БД хранится хеш секрета и хеш токена. Отозванная установка не восстанавливает доступ повторным запросом. Лимит — 60 новых регистраций в минуту с одного адреса, позволяющий подключить 50 ПК за одним NAT; общий активный лимит задаётся сервером, по умолчанию 500.

Это намеренно открытое подключение к одному настроенному кабинету: любой обладатель приложения может добавить собственный ПК, но не читать список чужих устройств, видео или управлять экзаменом. Повторная установка сохраняет профиль. Удаление профиля вручную создаёт новую установку; этот механизм не является аппаратной идентификацией ПК.

## GUARDED: реализовано и границы

Используется точная идентичность окна HWND + PID + время старта + путь программы. Перехватываются Alt+Tab, Win, PrtScn, Ctrl+C/V/X, переключение вкладок и ряд обходных сочетаний; очищается буфер обмена, перекрываются другие мониторы, фокус возвращается к окну теста. Встроенный QtWebEngine разрешает навигацию только внутри одного origin и запрещает новые окна, скачивание и выбор файлов. Потеря сервера более 10 секунд, закрытие окна, отказ защиты и перезапуск агента создают техническую блокировку.

Ctrl+Alt+Q и кнопка «Преподаватель» открывают экран с паролем. Продолжение и завершение создают серверную команду для конкретных device/exam/version/lock; токен агента сам по себе не разрешает снять блокировку. Пароль не сохраняется. Неверные пароли ограничиваются пятью попытками в минуту на кабинет; завершение разрешено при отказе камеры. Подмена heartbeat на OPEN/COMPLETED и повтор устаревшей команды проверяются тестами.

Это пользовательский процесс, без аттестации ОС. Завершение процесса с повышенными правами, Ctrl+Alt+Del, перезагрузка, другой пользователь и административный обход не предотвращаются. Тест жизненного цикла хуков выполняется отдельно с QORGAU_TEST_INPUT_HOOKS=1 на выделенном тестовом рабочем столе. Автотесты API и правил не доказывают невозможность обхода Windows. Протокол реальной проверки: WINDOWS_ACCEPTANCE.md.


## Учётные записи и данные

Кабинет: Argon2, HttpOnly/Secure/SameSite=Strict cookie, проверка origin и CSRF для изменений. Каждое устройство получает отдельный токен. Подготовленный EXE содержит только ограниченное право регистрации аудитории, адрес сервера и параметры подключения. Отзыв пакета останавливает новые регистрации, отзыв устройства прекращает действие ранее выданного токена. Отзыв работающего устройства запрещён до завершения сеанса.

События, клипы, отчёты и команды проверяют принадлежность кабинету. Секреты не хранить в репозитории и скриншотах. `.local` содержит закрытые тестовые профили и свидетельства проверки. Имена студентов — подписи преподавателя, не биометрическая идентификация.

Камера включается явно, звук не записывается. Сервер хранит фрагменты событий 7 дней; преподаватель может продлить срок с причиной, операция попадает в аудит. Таймер удаления обрабатывает только завершённые экзамены. Метаданные и история решений сохраняются после удаления видео. Резервные копии содержат видео до ротации семи архивов: обычно ещё до 7 дней; после неуспешных копирований архивы могут храниться дольше, это требует контроля оператора.

Локальные отправленные клипы удаляются после подтверждения сервера; буфер без событий очищается. Недоставленные клипы завершённых экзаменов удаляются по сроку 7 дней при работающем агенте либо следующем запуске, с записью причины в журнал. Выключенный компьютер не может выполнить очистку. Активные доказательства при заполнении диска не удаляются: захват сообщает техническую ошибку. Локальное шифрование средствами приложения пока не реализовано; управляемый ПК должен использовать отдельную учётную запись и защиту диска организации.

## Native Messaging

Вместо поиска «последнего профиля» используется явная привязка: каталог агента, server/account/device, origin расширения и UUID браузерного профиля. События принимаются только при свежем lease, совпадении экзамена и случайной привязке текущего процесса. Второй профиль браузера не получает данные первого. Протокол и отрицательные сценарии покрыты тестами; реальная установка расширения на целевой Windows остаётся пунктом приёмки.

Однократная подготовка сотрудником: установить распакованное расширение из `extension/`, открыть его страницу настройки, скопировать ID и UUID. Затем запустить:

```powershell
Qorgau-Student.exe --data "ПОЛНЫЙ_КАТАЛОГ_ЗАРЕГИСТРИРОВАННОГО_АГЕНТА" --install-extension ID_РАСШИРЕНИЯ --browser-instance UUID_ПРОФИЛЯ --browser edge
```

Меняется только Native Messaging registration текущего пользователя (HKCU). Повторная привязка к другому профилю требует явного `--replace-binding` в `scripts/install_native_host.py`. Расширение наблюдает вкладки; оно не заменяет механизм блокировки ОС.

## Испытательный контур Safe Exam Browser

На Windows 11 Pro встроенный Microsoft Keyboard Filter не является поддерживаемым вариантом. Подготовлен экспериментальный адаптер официального Safe Exam Browser: конфигурация с обязательной службой, отдельным рабочим столом, ограничениями сочетаний клавиш, буфера обмена и переходов; локальный мост передаёт команды блокировки/продолжения/выхода. Протокол проверен по официальному исходному коду и локальными HTTP-тестами, но живой совместный запуск SEB ещё не выполнен.

Пакет сотрудника: `Qorgau-SecurityBridge.exe` и `Prepare-Qorgau-Exam.ps1`. На отдельном тестовом профиле установить подписанный SEB со службой из [официального источника](https://safeexambrowser.org/download/), зарегистрировать Qorgau, назначить браузерный HTTPS-сеанс. Запустить PowerShell-скрипт с `-Profile` и сохранить пароль сотрудника. Скрипт создаёт `.seb`, но не включает политики и не запускает защищённый сеанс самостоятельно. Открывать `.seb` после старта сеанса Qorgau. После проверки выйти по паролю сотрудника, затем остановить мост.

**Ограничение:** мост пока работает с правами пользователя и доверяет его локальному журналу. Нет защищённого привилегированного Qorgau IPC, аттестации запущенного SEB и подтверждённой защиты от подмены журналов. Поэтому эта интеграция не даёт оснований включать STRICT или обещать невозможность обхода.

## Приёмка на отдельном профиле

Зафиксировать редакцию/сборку Windows, версию SEB, права студента, один монитор, SHA-256 EXE, камеру и версию правил. Сначала проверить аварийный выход по паролю сотрудника. Для каждой попытки записать ожидаемое/фактическое поведение и видео: Alt+Tab, Alt+F4, Win, Win+R, Win+Tab, Ctrl+Esc, Ctrl+Shift+Esc, Ctrl+Alt+Del, переключение рабочих столов, запуск/закрытие процессов, вставка текста, новая вкладка, чужой URL, внешняя программа, перезапуск агента и моста, отключение камеры и сети, завершение преподавателем.

Принятие STRICT возможно только после устранения обходов, проверки защищённого канала и положительного протокола восстановления. Администратор ОС, загрузка иной ОС, физическое отключение питания и телефон вне кадра не входят в заявляемую защиту.

Источники: [Microsoft Keyboard Filter](https://learn.microsoft.com/en-us/windows/configuration/keyboard-filter/), [варианты kiosk](https://learn.microsoft.com/en-us/windows/configuration/kiosk/), [руководство SEB](https://safeexambrowser.org/windows/win_usermanual_en.html), [исходный код SEB Windows](https://github.com/SafeExamBrowser/seb-win-refactoring).
