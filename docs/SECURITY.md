# Защита Qorgau: угрозы, меры и пределы

Актуально для 0.3.1. Проверка относится к нашему коду, локальным тестовым сеансам и открытым исследованиям. Атаки на чужие экзаменационные системы не проводились.

## Модель доверия

Преподаватель управляет сервером и выбирает режим. Агент работает на Windows-компьютере аудитории под обычной учётной записью. Пароль преподавателя проверяется на сервере; на ученическом компьютере не сохраняется. Видеокадры обрабатываются локально, события и короткие доказательные фрагменты отправляются серверу учебного заведения.

`GUARDED` — ограничение интерактивной пользовательской сессии: одно выбранное окно, перехват клавиш/мыши, фоновые экраны и остановка при технических сбоях. Это не граница безопасности ядра Windows. `STRICT` остаётся недоступным. Пользователь с правами администратора, доступом к файлам агента или возможностью завершать его процесс находится вне защищаемой этим прототипом модели.

## Что нашли и что сделали

| Риск / дыра | Реализованная мера | Остаточное ограничение |
|---|---|---|
| Переключение Alt+Tab, Win, Ctrl+Esc, снимок экрана | Win32 low-level hooks; блокировка PrintScreen и сочетаний, проверка активного окна каждые 100 мс | Ctrl+Alt+Delete, другой desktop, отключение питания требуют политики ОС |
| Копирование задания / вставка ответа | Ctrl+C/V/X, Shift+Insert/Delete, контекстное меню и боковые кнопки мыши запрещены; очистка clipboard в активном режиме | Не закрывает собственные команды экспорта внутри произвольного разрешённого приложения |
| Доступ к соседнему окну того же процесса | Разрешён конкретный HWND + PID + время запуска процесса + путь; проверка подмены и закрытия | Модальные окна тоже запрещены; совместимость конкретной системы надо проверить заранее |
| Выход из браузера через вкладку, адресную строку, popup, файл или iframe | Qorgau Browser: один view, проверка origin, запрет новых окон, скачиваний, file/javascript-навигации и контекстного меню | Сайт с внешним SSO/iframe потребует заранее спроектированного allowlist; поддомены по умолчанию запрещены |
| Попытка включить защиту обычного Chrome, оставив доступ к его интерфейсу | Для веб-сеанса GUARDED сервер требует Qorgau Browser; известные браузерные .exe из выбора окна не допускаются как защищённые приложения | Произвольный переименованный браузер нельзя надёжно распознать по имени; выбор доверенного приложения — обязанность администратора |
| Телефон кратко исчезает из кадра / взгляд возвращается | Защёлка LOCKED; возврат к норме не разблокирует; новый цикл только по команде преподавателя | Невидимый камерой телефон или наушник не обнаруживается программно |
| Камера выключена, кадр перестал обновляться, запись сломалась | Блокировка при ошибке камеры/кодирования; точное повторение кадров более 5 с считается неисправностью | Это не liveness. Зацикленное видео с изменяющимися кадрами и виртуальные камеры не распознаются надёжно |
| Сеть отключена в середине экзамена | В GUARDED после 10 с без успешной синхронизации блокировка; журнал/видео сохраняются, повторная доставка | Офлайн-разблокировки паролем нет. После восстановления сети доступны пароль или завершение из кабинета |
| Агент упал / был перезапущен | Восстановленный RUNNING становится LOCKED; новый lock_id делает старую разблокировку непригодной | Службы-наблюдателя, гарантированного автозапуска и защиты процесса от администратора ещё нет |
| Поддельный heartbeat «разблокировано» | Сервер требует подтверждение существующей команды UNLOCK/END для перехода LOCKED→OPEN; сброс RUNNING→READY отвергается | Скомпрометированный агент способен подделывать новые наблюдения. Нужны защищённая установка и аттестация |
| Повтор старой команды разблокировки | exam_id, lock_id, expected_version, срок команды и дедупликация идентификаторов | Учётная запись преподавателя должна быть защищена отдельно |
| Перебор пароля на экране ученика | Argon2 на сервере, максимум 5 неудач/минуту на владельца, счётчик хранится в SQLite; аудит без пароля | Скомпрометированная ОС может перехватить ввод; пароль вводят только на доверенном ПК |
| Удалённое управление, второй экран | Проверка Windows Remote Session; изменение числа экранов блокирует, все экраны получают фон ограничения | Не все программы удалённого доступа и не все виртуальные дисплеи обнаруживаются |
| Подмена файлов датасета, утечка кадров train→test | SHA-256, контроль ZIP-манифеста, групповые разделения public, оценка gaze по невиданному участнику | Public-группы выведены из имён файлов, не являются доказанными ID людей |
| Ложная тревога из-за естественных движений глаз | Восемь позиций калибровки, три независимых счётчика, спорные случаи REVIEW, решения преподавателя | На двух участниках невозможно доказать качество на всей аудитории; неизвестное наблюдение не означает норму |

В коде: `agent/windows_guard.py`, `agent/exam_browser.py`, `agent/exam_ui.py`, `agent/client.py`, `backend/proctor/app.py`. Регрессионные проверки: `tests/test_guard.py`, `tests/test_rules.py`, `tests/test_agent.py`, `tests/test_api.py`.

## Управляемая аудитория

Для реального экзамена подготовить отдельную стандартную Windows-учётную запись, запретить запуск посторонних программ через AppLocker/WDAC, настроить Assigned Access/Shell Launcher, права на папку агента, автоматический запуск, TLS и правила сети. Для подавления системных сочетаний использовать Windows Keyboard Filter на поддерживаемой редакции; обычный Python hook не заменяет этот компонент. Эти системные политики Qorgau автоматически не меняет.

Требуются отдельный администраторский аварийный вход, проверенный сценарий восстановления и проверка работы с необходимыми средствами доступности. Второй телефон вне кадра, подмена человека и сговор требуют организационных мер и наблюдения преподавателя. Детектор не устанавливает намерение фотографировать монитор: видимый телефон — наблюдаемый факт, попытка съёмки — предмет проверки.

## Данные и хранение

На сервере находятся токены в виде хешей, Argon2-хеш пароля, события, аудит и клипы. На агенте находится его bearer-токен, текущий журнал, очередь видео и миниатюры событий. При выходе из браузерного сеанса ответы остаются в открытом окне; преподаватель отдельно убеждается, что студент отправил тест.

Для LAN обязателен HTTPS: агент отвергает обычный HTTP, кроме loopback. Первый кабинет создают локально до публикации сервера. Включить `PROCTOR_SECURE_COOKIE=1` за HTTPS и указать разрешённый origin панели. Нет телеметрии с учебными кадрами в облако, аудиозаписи или отправки лиц внешним API. Загрузка моделей — отдельный явный шаг подготовки; готовый клиент не скачивает веса во время экзамена.

Установка должна определить срок хранения, ответственного и доступ к записям. Автоматическая политика удаления пока не реализована. Исходные фото/видео тренировочного пакета не входят в Git и релиз. Оригиналы и согласия участников хранятся у команды; наличие согласий самим архивом не подтверждается.

## Приёмка на целевом Windows-ПК

В контролируемом тестовом сеансе проверить: выбор окна, Alt+Tab/Win/PrtScn/clipboard, клик на другом мониторе, закрытие окна, выключение камеры, отключение сети, правильный/неправильный пароль, повтор команды и завершение из кабинета. Проверить, что после завершения клавиши и окна снова доступны. В CI проверяются Windows API, импорт и инференс упакованного приложения; CI не заменяет эти интерактивные испытания.
