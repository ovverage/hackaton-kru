# Qorgau — спецификация нового дизайна

Источник истины — экраны в `html/` (открываются в браузере без интернета) и их снимки в `png/`. Этот файл объясняет правила, по которым они собраны, и как каждый экран ложится на код репозитория `hackaton-kru`.

## 1. Идея

**Бланк ответов.** Ученики в Казахстане знают бланки ЕНТ: закрашиваешь кружок — выбрал ответ. В Qorgau закрашенный кружок показывает состояние:

| Кружок | Значит |
| --- | --- |
| закрашен графитом | пишет тест / готово |
| пустой с обводкой | ждёт старта / ещё не готово |
| пунктир | нет связи / Qorgau не открыт |
| закрашен красным | тест на паузе, ждёт преподавателя |
| жёлтая точка в углу кружка | есть событие, которое ждёт решения |
| закрашен бирюзой | выбранный пункт меню, «на связи», текущий шаг |

**Метки регистрации** (чёрные квадратики 9×9 по углам, как на сканируемом бланке) стоят только там, куда «смотрит» система: схема аудитории, предпросмотр камеры, видео события, сетка готовности, правила. Не размножать их по другим блокам.

**Тихо, когда всё хорошо; громко, когда нужен преподаватель.** Нормальное состояние нейтральное (графит, без зелёного). Цвет появляется только у исключений: красный — пауза, жёлтый — ждёт решения или нужно действие.

## 2. Токены

Все значения — в `tokens.json`; готовый CSS с переменными — `html/qorgau.css` (`:root`).

- Цвета: paper `#F4F5F7`, sheet `#FFFFFF`, graphite `#22252B`, pencil `#5B6270`, rule `#D9DDE3`, ink `#0B6474`, amber `#9A5B07` / `#F0B33E`, red `#B5302F` / `#C83A36`. Контраст текста проверен (≥4.5:1).
- Шрифт: **Geologica** (покрывает казахскую кириллицу Ә Ғ Қ Ң Ө Ұ Ү Һ І). Веб — `fonts/Geologica-Variable.woff`; Qt — четыре статических TTF из `fonts/static/`. Лицензия OFL — добавить в `THIRD_PARTY_NOTICES.md`.
- Шкала: 12 / 14 / 16 / 21 / 24 / 36 / 48 / 72. Цифры моноширинные по ширине (`tabular-nums`).
- Скругления по иерархии: бланк 4, поле 8, кнопка и панель 10, модалка 16, пилюля и кружок — полные. Тени только у всплывающего.
- Минимальная высота нажимаемого элемента — 44 px (мелкая кнопка 36 px).

## 3. Компоненты

Классы — из `html/qorgau.css`; там же точные размеры.

- **Bubble** `.bub` + `on | pause | warn | ink | off` + `flag`; размеры `xs sm (по умолчанию 16) lg`.
- **Шаг** `.bub-num` + `done` (графит с галочкой) | `now` (бирюзовая обводка с ореолом) | `skip` (пунктир) | обычный (номер в обводке). Шаги соединены вертикальной линией.
- **Бланк** `.sheet` + четыре `.reg` по углам.
- **Схема аудитории** `.plan-wrap > .plan + .tally`: ряд = метка ряда (чёрная полоска 7×20 + «ряд N») + 3 места + проход (пунктирная вертикаль) + 3 места; сверху плашка «Доска и стол преподавателя». Место = кружок 30 px + номер. Справа итоги: крупное число 36 px + кружок + подпись.
- **Сетка готовности** `.table.omr`: строка на компьютер, столбцы-требования с кружком по центру, чередование фона строк, последняя колонка «Что сделать» (жёлтым, если действие нужно).
- **Счётчики отметок** `.cnts > .cnt`: стрелка (↓ ← →) + 3 маленьких кружка, закрашено столько, сколько отметок в текущем круге.
- **Пилюли** `.pill` + `pause | warn | ok | off`.
- **Кнопки** `.btn` + `primary` (бирюза) | `dark` (графит, «Это нарушение», «Позвать преподавателя») | `quiet` (текстовая) | `danger` (красный текст); размеры `sm lg`, `block`.
- **Поля** `.field`, `.input`, `.select` (своя стрелка), `textarea.input`.
- **Меню кабинета** `.nav a > .opt`: пункты как варианты ответа, выбранный — закрашенный бирюзовый кружок с ореолом и полужирный текст. Иконок в меню нет. Счётчик справа: красный (пауза) или жёлтый (события).
- **Верхняя строка** `.topbar`: слева часы `.clock` (крупное время, дата, во время теста бирюзовым «тест идёт N мин»), справа «Сервер на связи». Хлебных крошек нет.
- **Кадр камеры** `.cam`: тёмная сцена 16:9, белые метки регистрации, рамка обнаружения `.det` с подписью («телефон 93%»), таймкод `.tc`, кнопка воспроизведения `.play`.
- **Примечания** `.note` + `warn | ink`.
- **Модальное окно** `.modal` (760) / `.modal.wide` (980–1080): шапка, тело, подвал с кнопками справа.

Иконки: [Lucide](https://lucide.dev) (в вебе уже есть `lucide-react`), обводка 1.75, размеры 15/18/22. В меню кабинета иконки заменены кружками.

## 4. Словарь интерфейса

Тексты переписаны проще. Одно действие называется одинаково везде.

| Было | Стало |
| --- | --- |
| Заблокирован / Заблокированные | На паузе |
| Блокировка по правилам | Тест на паузе |
| Разблокировать тест / Разрешить продолжить | Продолжить тест |
| Заблокировать | Поставить на паузу |
| Завершить контроль · пароль преподавателя | Завершить контроль на этом компьютере |
| Подтвердить событие / Отклонить событие | Это нарушение / Нарушения нет |
| На проверке / Подтверждено / Отклонено | Ждёт решения / Нарушение / Нарушения нет |
| Проверка событий (меню) | События |
| Текущие компьютеры | Пишут тест |
| Требуют внимания | Ждут решения |
| Готово (камера) | Проверить камеру → в окне: «Использовать эту камеру» |
| Изменить камеру | Проверить снова |
| Выбрать открытое окно | Выбрать окно программы |
| Преподаватель · Ctrl+Alt+Q | Позвать преподавателя Ctrl+Alt+Q |
| Верните взгляд на монитор | Смотрите на экран |
| Сервер подключён | Сервер на связи |
| Цикл N | круг N (отметки за взгляд) |

Названия событий (`eventNames` в `web/src/types.ts`):
TEACHER_REQUEST «Ученик позвал преподавателя», GAZE_DOWN/LEFT/RIGHT «Взгляд вниз/влево/вправо», PHONE_DETECTED «Телефон в кадре», PHONE_AIM_REVIEW «Возможная съёмка телефоном», SECOND_FACE_REVIEW «Второе лицо в кадре», FREQUENT_GAZE_REVIEW «Частые отвлечения», FACE_ABSENCE_REVIEW «Лица не видно», FACE_ABSENCE_TECHNICAL «Лица не видно 10 секунд», CAMERA_UNAVAILABLE «Камера недоступна», CAMERA_FROZEN «Камера замерла», TARGET_CLOSED «Окно теста закрыто», BROWSER_ATTEMPT «Попытка открыть другой сайт», ENVIRONMENT_ATTEMPT «Попытка выйти из теста», REMOTE_SESSION «Удалённый рабочий стол», DISPLAY_CHANGED «Изменилось число экранов», SERVER_UNAVAILABLE «Нет связи с сервером», GUARD_UNAVAILABLE «Защита окна не работает», AGENT_RESTARTED «Qorgau перезапущен», AGENT_FAILURE «Сбой Qorgau», HEAD_TURN_REVIEW «Поворот головы», EXTENSION_DISCONNECTED — без изменений.

Причины паузы для ученика (`REASONS` в `agent/student_state.py`) пишутся как одно спокойное предложение о том, что произошло, без обвинения: «Камера заметила телефон», «Три раза долго смотрели вниз», «Лица не видно 10 секунд», «Вы позвали преподавателя», «Окно теста закрыто», «Пропала связь с сервером» и т. д. Время события добавляется в заголовке: «Камера заметила телефон в 09:52».

Не писать через «·» строки вида «A · B · C» — вместо этого запятые или отдельные элементы. Без капса в подписях, без «→» в кнопках.

## 5. Экраны и где они в коде

### Приложение ученика (PySide6)

| Экран | Файл макета | Код |
| --- | --- | --- |
| Первое подключение | `exe-01-connect` | `agent/desktop.py` → `StudentWindow.build_auto_setup`, `registration_failed` |
| Подготовка компьютера | `exe-02-prep` | `agent/desktop.py` → `build_dashboard`, `refresh`; тексты `agent/student_state.py` → `present` |
| Проверка камеры | `exe-03-camera` | `agent/camera_setup.py` → `CameraSetup` (ветка без калибровки) |
| Выбор окна программы | `exe-04-window` | `agent/exam_ui.py` → `TargetPicker` |
| Меню в трее | `exe-05-tray` | `agent/desktop.py` → `create_tray`, `refresh` |
| Тест + напоминание о взгляде | `exe-06-exam-gaze` | `agent/exam_browser.py` → `teacher_button`; `agent/exam_ui.py` → `GazeWarning`, `ExamController.tick` |
| Тест на паузе | `exe-07-pause` | `agent/exam_ui.py` → `LockScreen` |

Детали:

- **Подготовка.** Заголовок — состояние из `present()`. Под ним «У преподавателя этот компьютер называется <имя>». Три шага:
  1. «Камера»: `done`, если камера работает; иначе текущий шаг. Справа «работает» или «проверена в ЧЧ:ММ», если время известно. Внутри — выбор камеры, кнопка «Проверить камеру»/«Проверить снова», строка «Взгляд: на экран/вниз/…» из `gaze_diagnostics`.
  2. «Окно программы»: `skip` и «не нужно для сайта», пока окно не выбрано; `done` с названием окна, если выбрано (кнопка «Изменить окно»).
  3. «Начало теста»: `now` и «ждём преподавателя», когда сеанс назначен; обычный и «сеанс ещё не назначен» без сеанса; `done` во время теста.
  Внизу полоса: «Во время теста Qorgau отмечает события и сохраняет короткие видео. Звук не записывается.» Шапка: логотип и пилюля «На связи с сервером» (или «Нет связи, переподключаемся» жёлтым).
- **Логотип.** Закрашенный кружок с ножкой справа — буква q: круг r=8 в (11,12) и скруглённый прямоугольник x 15.5, y 4, 4.5×20 на холсте 26×26, цвет ink. В Qt нарисовать `QPainter` в `icon()` вместо буквы «q» в квадрате.
- **Проверка камеры.** Кадр с белыми метками по углам и пунктирным овалом-подсказкой для лица (рисовать поверх pixmap). Под кадром заголовок «Посмотрите на экран и подтвердите камеру», пояснение и три подсказки-пилюли. Внизу «Отмена» слева, «Использовать эту камеру» справа (текст кнопки проверяют тесты).
- **Напоминание о взгляде.** Жёлтая плашка шириной ~520 px сверху по центру: иконка глаза, «Смотрите на экран» 24 px, строка «Взгляд вниз дольше 5 секунд засчитывается» (направление — из `attention_direction`; для UP строку не показывать), справа секунды «2,1 с», снизу полоса прогресса `gaze_seconds / 5`. Окно по-прежнему не берёт фокус и пропускает клики.
- **Кнопка в Qorgau Browser.** Графитовая, справа сверху: колокольчик, «Позвать преподавателя», рамка-клавиша «Ctrl+Alt+Q».
- **Пауза.** Верх ~240 px красный (`redFill`): логотип белым, справа «<ПК>, ЧЧ:ММ»; «Тест на паузе» 24 px; «Позовите преподавателя» 72 px одной строкой (текст заголовка проверяют тесты — оставить точно). Ниже белая часть в две колонки:
  - слева причина (21–24 px), два предложения пояснения и рамка «Для преподавателя» (пароль, «Продолжить тест», текстовая кнопка «Завершить контроль на этом компьютере», при сбое камеры — «Восстановить камеру»);
  - справа «Что заметила камера»: миниатюра с метками регистрации и временем, подпись, ниже строки других событий этого круга.
  Внизу мелко: «Событие — повод посмотреть запись. Решение о нарушении принимает преподаватель.» Всё должно помещаться в 1366×768 без прокрутки.

Детали:

- **Схема аудитории.** Компьютеры сеанса по имени в естественном порядке (PC2 перед PC10), по 6 в ряд, проход после третьего. Количество мест в ряду — одна константа (`SEATS_PER_ROW = 6`, `AISLE_AFTER = 3`), чтобы потом подогнать под реальную аудиторию. Номер места — последние цифры имени (`K301-PC14` → `14`), иначе порядковый. Состояние кружка:
  - пауза → `pause`;
  - нет связи → `off`;
  - RUNNING и OPEN → `on`;
  - READY → пустой.
  Флажок — если у компьютера есть события «ждёт решения». Клик по месту открывает карточку компьютера. До сеанса показываются все зарегистрированные неотозванные компьютеры: онлайн — пустой кружок (с флажком, если не готов по `preparationIssue`), офлайн — пунктир.
- **Итоги справа:** пишут тест, на паузе (красным, «ждут вас»), ждёт старта, нет связи; под чертой — «событий ждут решения» (жёлтым, ссылка на очередь). Заменяют четыре карточки `session-overview`. Полоса `class-session` уходит в шапку страницы: H1 = название сеанса, под ним группа, среда теста и время начала; справа выбор сеанса, «Начать на N компьютерах» (если есть READY), «Завершить сеанс».
- **Таблица «Пишут тест».** Колонки: компьютер (кружок, «номер имя», под ним «<ПК>, <состояние>»), отвлечения (счётчики ↓←→), последнее событие (под ним время; жёлтым «ждёт решения»), стрелка. Колонку значков «камера, взгляд, защита» убрать: если что-то не работает, писать это жёлтым в строке под именем («камера не отвечает»). Над таблицей красная полоса «N компьютера на паузе ждут вашего решения: 07 и 14 → Открыть», если есть паузы. Поиск и постраничный вывод остаются.
- **Очередь «Ждут решения».** Список без карточек, разделён линиями: миниатюра 104×58 с длительностью, название, «номер имя», время (красным «тест на паузе», если пауза).
- **Часы в шапке.** Текущее время и дата (`ru-RU`). Во время сеанса — «тест идёт N мин» от времени начала. Если в данных нет времени старта, брать `exam.created_at` и писать «сеанс с ЧЧ:ММ».
- **Разбор события.** Видео слева с метками регистрации и рамкой обнаружения, если есть координаты. Под ним шкала записи: дорожка клипа, отрезок эпизода (ink), метка срабатывания (красная), пропуски (жёлтая штриховка); данные из `media.clip_start/clip_end`, `e.start`, `e.at`, `media.gaps`. Проверьте единицы `gaps` в коде агента. Справа время начала, срабатывания, длительность и «Хранится до» со ссылкой «продлить на 7 дней», комментарий, две крупные кнопки одна под другой («Нарушения нет», «Это нарушение»), история.
  Абсолютное время: срабатывание = `created_at`, начало = `created_at − (at − start)`. Если это неверно для ваших данных — оставить относительные секунды.
- **Компьютеры.** Сетка готовности:
  - связь — online;
  - камера — `camera && !camera_fault`;
  - взгляд — `gazeEnabled`;
  - защита окна — `window_guard`;
  - Qorgau Browser — есть цель `qorgau-browser`;
  - версия — `capabilities.agent_version`.
  Сверху крупно «N из M готовы к тесту» (по `preparationIssue(d, "BROWSER") === null`). «Что сделать» — из `preparationIssue`, переписанное повелительно для учителя («Ученику: нажать „Проверить камеру“», «Скачать Qorgau 0.4.8 на этот компьютер»). Отзыв доступа — тихая иконка-кнопка с `aria-label`, подтверждение через существующую модалку. Блок скачивания — снизу.
- **Правила.** Один бланк с метками, три группы («Ставят тест на паузу», «Уходят вам на проверку, тест продолжается», «После паузы»), правила пронумерованы 1–8, справа у каждого схема «условие → пауза/проверка». Тексты брать из макета; пороги не менять — они берутся из `shared/rules.py`.
- **Телефон.** Сайдбар уходит наверх, схема — 6 мест в ряд без подписей рядов (только полоски), итоги под схемой, таблица прокручивается в своей рамке. Отдельный мобильный экран `web-04-room-phone` — ориентир, как это должно ощущаться.

## 6. Что не меняется

Логика правил, пороги, API, протокол агента, защита окна и браузера, хранение записей, проверки перед стартом. Это смена оформления и текстов. Новые элементы (схема, итоги, шкала записи, сетка готовности, часы, полоса прогресса взгляда) строятся только из уже существующих данных.
