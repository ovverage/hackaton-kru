# Qorgau — локальный прокторинг

Рабочая первая итерация проекта для **Qostanai Industry Hackathon**, кейс 3. Преподаватель работает в веб-панели, на компьютере ученика запускается локальный агент. Сам тест остаётся на внешнем сайте или в установленном приложении.

**Текущая сборка: 0.1, режим наблюдения. Это ещё не защищённый экзаменационный клиент.** Состояние `LOCKED` работает в правилах, панели и журнале; Windows, горячие клавиши и внешние приложения эта версия физически не блокирует. Сервер намеренно не разрешает режим `STRICT`.

## Что уже работает

- Первый вход с созданием локальной учётной записи преподавателя; пароли Argon2, сессии HttpOnly.
- Подключение компьютеров одноразовым кодом, отдельный токен каждого агента.
- Создание сеанса с выбором доступного браузера + адреса сайта либо локально разрешённого приложения.
- Синий веб-кабинет: таблица учеников, поиск и фильтр внимания, отдельные счётчики, просмотр видео и решения в правой панели. Обновления по WebSocket.
- Постоянная регистрация рабочего места; имя ученика назначается преподавателем на каждый сеанс. Исторические отчёты сохраняют прежние имена.
- Три независимых счётчика `DOWN`, `LEFT`, `RIGHT`. Один эпизод от 5 секунд → один балл; третий в одном направлении → `LOCKED`.
- Телефон: два обнаружения с уверенностью ≥0,65 на интервале ≤0,6 с → `LOCKED`, без накопления трёх баллов.
- Второе лицо ≥1 с, отсутствие лица ≥5 с и частые короткие отвлечения → ручная проверка.
- Подтверждение/отклонение события с причиной и историей решений. Отклонение не разблокирует автоматически.
- Разблокировка преподавателем с проверкой актуальной версии и идентификатора блокировки. Новый цикл обнуляет текущие счётчики; вся история остаётся.
- Завершение контроля отдельного ученика, история сеансов, таблица результатов, выгрузка CSV.
- Приём MP4/WebM, проверка доступа, воспроизведение с переходом к моменту срабатывания, поддержка HTTP Range.
- Python-агент: работа в системном трее, служебное окно по нажатию значка, запуск выбранного локального исполняемого файла без shell, журнал на диске, очередь событий, повторная доставка и защита от повторного выполнения команд.
- Отдельный, явно помеченный стенд с четырьмя виртуальными учениками. Сценарии прогоняются через тот же модуль правил.

## Что реализовано в коде, но требует проверки на целевом ПК

- Экспериментальная камера: локальный YOLO для `cell phone`, MediaPipe Face Landmarker для лиц и калибруемых признаков глаз/головы. Калибровка четырёх позиций обязательна. Точность на реальных людях **не измерена**; это не измеритель точного направления взгляда.
- Фрагменты камеры: до 10 с до срабатывания и 5 с после, H.264/MP4, без звука, очередь отправки. Кодирование проверено на синтетических кадрах; съёмка реальной камерой в этой сессии не выполнялась.
- Расширение Chrome/Chromium/Edge + Native Messaging: передача активного сайта и потери фокуса во время сеанса. Протокол хоста проверен автоматическим тестом; установка расширения и поведение в настоящем браузере ещё не проверены. Оно **не запрещает** переходы и смену вкладок.

## Агент на компьютере ученика

Фоновый агент с системным треем на PySide6 находится в `agent/desktop.py`. Обычного рабочего интерфейса для ученика нет: тест открывается в выбранном преподавателем браузере или приложении. Запуск из проекта:

```sh
.venv/bin/python -m pip install -e '.[desktop]'
npm run student
```

На Windows после установки зависимостей можно дважды открыть **Start-Student.cmd**. Для исходной версии Python нужен на компьютере; переносимая сборка содержит свой интерпретатор.

Администратор один раз вводит три поля:

1. **Адрес сервера** — например, `https://proctor.university.example`, без `/api` и токена в адресе.
2. **Название компьютера** — например, `Аудитория 301 · ПК-01`. Это имя рабочего места, не ученика.
3. **Одноразовый код** — из веб-панели «Компьютеры → Подключить компьютер». Код действует 5 минут и подходит только для одного подключения.

После регистрации окно скрывается в трей. На следующих запусках агент использует сохранённый токен и начинает работу без окна. По значку в трее можно открыть состояние компьютера, адрес сервера, назначенный сеанс и готовность камеры. Закрытие этого окна скрывает его и **не останавливает агент**. Пункт «Завершить агент» недоступен во время активного сеанса; самостоятельной разблокировки нет. Это ограничение интерфейса, не защита от завершения процесса средствами ОС.

Если в системе нет трея, окно остаётся доступным; его закрытие сворачивает приложение. `--show` принудительно открывает окно состояния. Повторный GUI-запуск с той же папкой данных не создаёт второй экземпляр. Реализация трея использует [QSystemTrayIcon](https://doc.qt.io/qtforpython-6/PySide6/QtWidgets/QSystemTrayIcon.html).

Перед каждым тестом преподаватель выбирает на сайте компьютеры, браузер/приложение, адрес теста и при необходимости имена учеников. Пустое имя на реальном ПК отображается как название рабочего места. Имя — назначение преподавателя, а не подтверждённая идентификация личности. Регистрация и токен компьютера остаются прежними между группами.

Кнопка **«Подготовить камеру»** открывает настройку локальных моделей, предпросмотр и калибровку четырёх направлений. Камера включается только после явного нажатия. Сбор калибровочных кадров не отправляется преподавателю. Нужны зависимости `[cv]`, модели и FFmpeg; без них интерфейс сообщает, что анализ не подготовлен. Во время активного теста перенастройка камеры недоступна. Готовность GUI не подтверждает точность CV на реальных людях.

Для сборки переносимого приложения **на целевой ОС**:

```sh
.venv/bin/python -m pip install -e '.[desktop,package]'
.venv/bin/python scripts/build_student.py
```

Результат: папка `dist/Qorgau-Student/`; на Windows — `Qorgau-Student.exe`, на Linux — `Qorgau-Student`. Передавать нужно всю папку. По умолчанию сборка включает интерфейс и связь, **без CV-библиотек**. Для полной сборки предварительно установить `[cv]` и добавить `--with-cv`; модели и FFmpeg подготавливаются отдельно. Текущая Linux-сборка проверена на этой машине; совместимость с другими дистрибутивами отдельно не подтверждена. Windows `.exe` собирается на Windows, а не на Linux. Установщик со службой и политиками Windows пока не готов.

## Быстрый запуск веб-панели

Нужны Python 3.12+ и Node.js 22.12+. Для камеры рекомендуется отдельная среда Python 3.12: совместимость MediaPipe с Python 3.14 не проверена.

Linux / macOS, из корня проекта:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-core.lock
.venv/bin/python -m pip install -e '.[test]'
npm --prefix web ci
npm run dev
```

Открыть **http://127.0.0.1:5173**. Сервер API запускается на `127.0.0.1:8000`.

Windows PowerShell:

```powershell
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements-core.lock
.venv\Scripts\python.exe -m pip install -e ".[test]"
npm --prefix web ci
npm run dev
```

Для запуска готовой сборки одним сервером:

```sh
npm run build
.venv/bin/python -m uvicorn backend.proctor.app:app --host 127.0.0.1 --port 8000
```

После сборки открыть **http://127.0.0.1:8000**. На Windows заменить путь Python на `.venv\Scripts\python.exe`. Приложение создаст `.local/proctor.sqlite3` и `.local/media/`. Пароля по умолчанию нет: преподаватель создаёт свой при первом открытии. Создание первого кабинета выполняйте локально до подключения к сети аудитории.

## Сценарий проверки за 5 минут

1. Создать кабинет → «Попробовать на стенде».
2. Выбрать четыре компьютера, Chrome и адрес внешнего теста → «Создать сеанс» → «Начать контроль».
3. Открыть ученика и трижды нажать «Взгляд вниз · 5 с». Проверить `3/3` только внизу и блокировку только этого ученика.
4. Открыть одно событие → написать причину → отклонить. Счётчик уменьшится, блокировка сохранится.
5. В карточке ученика выбрать «Разрешить продолжить», указать причину. Начнётся новый цикл `0/3`, история останется.
6. Проверить «Телефон»: немедленное критическое событие. Проверить «Второе лицо»: только очередь проверки.
7. Для проверки проигрывателя можно вручную прикрепить собственный **тестовый** MP4/WebM к тренировочному событию, максимум 50 МБ. На реальном устройстве запись через преподавательскую форму заменить нельзя.
8. Завершить контроль ученика, открыть «Сеансы и отчёты», скачать CSV.

Не выдавайте искусственные сценарии за работу компьютерного зрения. Для демонстрации CV нужны настоящий агент, камера, локальные модели и отдельный прогон на целевом ПК.

## Подключение локального агента

В панели: **Компьютеры → Подключить компьютер**. Код действует 5 минут и используется один раз.

На компьютере ученика, после установки Python-зависимостей проекта:

```sh
.venv/bin/python -m agent.client --enroll КОД --name "ПК-01 — Имя ученика" --server http://127.0.0.1:8000
.venv/bin/python -m agent.client
```

По умолчанию запускается агент в трее (при первом запуске — окно регистрации); установите `[desktop]`. `--show` открывает служебное окно, `--headless` запускает агент вообще без GUI и трея.

Данные агента: `~/.qorgau/config.json`, `~/.qorgau/journal.json`, `~/.qorgau/clips/`. Другая папка задаётся `--data PATH`. Не коммитьте токены, журналы и записи. В Linux файлы журнала и конфигурации создаются с правами `0600`; управление правами Windows ещё нужно настроить при установке.

Без подготовки камеры в служебном окне или параметра `--camera` агент **не включает камеру и не выполняет CV**. Это позволяет отдельно проверить связь, выбор среды и команды. Установка и регистрация ПК выполняются один раз, но калибровка взгляда относится к конкретному человеку: её нельзя считать настройкой администратора, подходящей всем ученикам. Автоматическая подготовка CV после перезапуска пока не реализована.

Агент автоматически обнаруживает Chrome/Chromium и Edge. Для внешнего приложения добавьте на самом компьютере запись в массив `targets` файла `config.json`, сохранив остальные поля:

```json
{
  "id": "exam-app",
  "name": "Установленная система тестирования",
  "kind": "APP",
  "executable": "C:\\Program Files\\ExamApp\\ExamApp.exe"
}
```

Только существующие локальные файлы попадают в список преподавателя. В веб-панели нельзя передать произвольную команду оболочки. Для группы нужен общий `id` среды на всех выбранных ПК, локальный путь может отличаться. На `START` агент запускает эту среду; на завершении контроля не закрывает внешний тест и не отправляет его ответы.

### Реальная камера — экспериментальный режим

В отдельной среде Python 3.12 установить `pip install -e '.[desktop,cv]'` и FFmpeg. Не устанавливать одновременно `opencv-python` и `opencv-python-headless` в одну среду камеры: калибровке требуется окно OpenCV.

Подготовить локальные модели из официальных источников:

- YOLOv8n или YOLO11n с COCO-классом `cell phone`: [документация Ultralytics](https://docs.ultralytics.com/modes/predict/).
- `face_landmarker.task`: [документация MediaPipe Face Landmarker](https://ai.google.dev/edge/mediapipe/solutions/vision/face_landmarker/python).

Модели не включены в репозиторий и автоматически не скачиваются агентом. Используйте доверенные файлы; зафиксируйте их версии и SHA-256 при подготовке демонстрации. Лицензии моделей и библиотек нужно учитывать при последующем распространении.

```sh
.venv/bin/python -m agent.client --camera 0 --phone-model models/yolo11n.pt --face-model models/face_landmarker.task
```

После запуска камера включится для калибровки. Для каждой позиции `SCREEN / DOWN / LEFT / RIGHT` нажмите Space и удерживайте взгляд: собираются 25 пригодных кадров. Escape отменяет калибровку. Неразличимые позиции не допускаются. После калибровки обработка кадров идёт только в состоянии `RUNNING`.

Один локальный инференс до 10 кадров/с, JPEG-буфер последних 10 секунд, асинхронное кодирование MP4. Утраченные интервалы не прибавляются к пятисекундному порогу. При недоступной камере создаётся техническое событие и состояние блокировки. Возврат камеры сам по себе блокировку не снимает.

Фрагменты частых отвлечений пока показывают только последние 10 секунд до срабатывания, а не все эпизоды за минуту. Полная непрерывная запись сеанса и сегментированный архив ещё не реализованы. При аварийном завершении незавершённый фрагмент в памяти может потеряться.

### Расширение браузера

1. Открыть страницу расширений Chrome/Chromium/Edge, включить режим разработчика и загрузить папку `extension/` как распакованное расширение.
2. Скопировать его ID и на том же компьютере выполнить:

```sh
.venv/bin/python scripts/install_native_host.py ID_РАСШИРЕНИЯ --browser chrome
```

Поддерживаемые значения: `chrome`, `chromium`, `edge`. Скрипт регистрирует Native Messaging host только в профиле текущего пользователя; Windows использует HKCU. Это инструмент разработки, не защищённая централизованная установка.

3. Перезапустить расширение. При активном сеансе появится `ON`, при состоянии блокировки `!`, при отсутствии связи `?`.

Хост использует `~/.qorgau` или `QORGAU_AGENT_DATA`. За пределами активного браузерного сеанса наблюдения не сохраняются. В событии на сервер передаётся только origin, без пути и параметров URL. Пока нет привязки к конкретному ID вкладки, отслеживания отключения расширения и запрета смены вкладки на том же origin. Дополнительные домены SSO нужно учесть в следующей версии политики.

## Как агент связан с сайтом

Агент инициирует только исходящие HTTPS-запросы. Входящий порт на ученическом ПК не нужен. Сервер хранит очередь команд, а агент забирает её примерно раз в секунду вместе с назначением сеанса. Веб-панель получает снимки состояния по WebSocket. Тяжёлые видеофрагменты отправляются отдельным рабочим потоком и не задерживают получение команд.

| Endpoint | Кто вызывает | Назначение |
|---|---|---|
| `POST /api/pairings` | Преподаватель с cookie-сессией | Создать одноразовый код |
| `POST /api/agent/enroll` | Администратор через агент | Передать `{code, name}`, получить `device_id` и индивидуальный `token` |
| `POST /api/agent/sync` | Агент с `Authorization: Bearer …` | Heartbeat, состояние, доступные среды, события и подтверждения; в ответ — сеанс, среда и команды |
| `POST /api/agent/media/{event_id}` | Агент с токеном | Передать видеофрагмент принадлежащего ему события |
| `POST /api/exams` | Преподаватель | Назначить ПК, среду и `student_names: {device_id: имя}` |
| `POST /api/devices/{device_id}/commands` | Преподаватель | `START`, `LOCK`, `UNLOCK`, `END_AND_RELEASE` |
| `POST /api/events/{event_id}/review` | Преподаватель | Сохранить решение, причину и ожидаемую версию события |
| `GET /api/snapshot`, `WS /ws/teacher` | Веб-панель | Состояния компьютеров, сеансы, события и результаты команд |

Ответ синхронизации содержит `exam_id`, `session: {title, group, room, student}`, `environment: {kind, target_id, url?}` и `commands`. Запрос включает `exam_id`, `state`, `events`, `targets`, `capabilities`, `acknowledgements`. Пароль преподавателя агенту не передаётся.

После назначения агент принимает сеанс. На `START` запускает разрешённый локальный файл выбранной среды; подтверждает команду только после её применения. При потере связи повторяет подключения, хранит события на диске и сохраняет блокировку. Через 6 секунд без heartbeat сайт показывает отсутствие связи. Команды имеют срок действия и идентификаторы; повторы не запускают тест заново. `UNLOCK` проверяет актуальные `lock_id` и версию состояния. Завершение контроля сохраняет отчёт, но не отправляет ответы и не закрывает внешний тест.

**Развёртывание:** в прототипе данные агента привязаны к папке `--data`, по умолчанию к профилю пользователя `~/.qorgau`. Для демонстрации регистрируйте агент в той же учётной записи ОС, под которой будут проходить тесты. Автозапуск при входе, установка на все профили, защищённая служба Windows и ACL общей папки требуют отдельного установщика; текущий запуск в трее не заменяет эту инфраструктуру.

## Локальная сеть аудитории

Разработка по умолчанию слушает только localhost. Для нескольких компьютеров понадобится один сервер в локальной сети, HTTPS с доверенным сертификатом и разрешённый origin веб-панели. Агент отказывается отправлять токен по обычному HTTP за пределы localhost. Обход проверки TLS не реализован.

Настройки окружения сервера:

| Переменная | Назначение |
| --- | --- |
| `PROCTOR_DATA` | Папка SQLite и видео; по умолчанию `.local` |
| `PROCTOR_ALLOWED_ORIGINS` | Допустимые origins через запятую для браузера и WebSocket |
| `PROCTOR_SECURE_COOKIE=1` | Обязательно при HTTPS-развёртывании |

Для демо на одной машине внешний интернет нужен только для самого внешнего сайта, если он не локальный. Правила, CV, API и хранение видео работают локально. Не запускайте несколько worker-процессов Uvicorn для тренировочного стенда: его временное состояние наблюдений хранится в памяти одного процесса.

## Критерии хакатона

[План защиты и демонстрации](docs/DEMO.md) связывает все шесть критериев (15 + 20 + 20 + 15 + 15 + 15 = 100) с конкретными действиями, измерениями и текущими ограничениями. В нём также есть пяти­минутный сценарий и ответы на вопросы жюри.

## Следующие обязательные этапы перед Demo Day

1. **Управляемый Windows 11 клиент:** системная служба, политика стандартного пользователя, kiosk/ограничение приложений, проверяемая блокировка горячих клавиш, восстановление после сбоев, установщик и защищённое аварийное снятие ограничений.
2. **CV на реальном стенде:** прогон с камерами аудитории, освещением, очками и разными пользователями; оценка ложных срабатываний и задержки; проверка порогов калибровки. Строгую блокировку нельзя включать по непроверенной эвристике взгляда.
3. **Видео:** непрерывные сегменты, устойчивое восстановление очереди после аварии, все интервалы частых отвлечений, политика хранения и удаления.
4. **Браузер и приложения:** привязка конкретного окна/вкладки, разрешённые SSO-адреса, защита от отключения расширения, проверка реальных систем тестирования.
5. **Разблокировка паролем сотрудника:** сейчас есть кнопка авторизованного преподавателя; отдельный офлайн-пароль/одноразовый код на компьютере ученика ещё не реализован.
6. **Репетиция аудитории:** HTTPS, минимум два физических ПК, потеря сети, перезапуск агента, проверка журнала и видео, затем питч по критериям хакатона.

Актуальное полное ТЗ: [docs/TZ_Qostanai_Proctoring_v2.docx](docs/TZ_Qostanai_Proctoring_v2.docx). В нём описан целевой продукт; перечень выше отражает фактическую готовность текущей реализации.
